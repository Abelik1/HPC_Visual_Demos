# Full 3-D galaxy-collision demo

`galaxy_collision_3d` is intentionally a second demo, not a replacement for
the fast restricted collision. It combines the Local Group encounter already
defined by this project with the direct three-dimensional N-body mathematics
demonstrated by [NBody-EuroHPC](https://github.com/albtad01/NBody-EuroHPC).

## Physical model

Every disc, bulge, and dark-halo super-particle has mass. Each acceleration is
the softened all-pairs force

```text
a_i = sum_j G m_j (q_j - q_i) / (|q_j - q_i|^2 + epsilon^2)^(3/2).
```

The cost is O(N^2) per force evaluation. `leapfrog` uses a second-order
kick-drift-kick update and is the default. `murb_kinematic` reproduces the
reference demo's ordinary constant-acceleration position/velocity update so
the two integration approaches can be compared from the same Solver menu.
The encounter begins with this project's Milky Way/Andromeda separation,
radial velocity, transverse-velocity estimate, and barycentric bulk motion.

The CPU implementation evaluates identical equations in bounded NumPy tiles,
so memory is O(N) plus one tile pair rather than O(N^2). The CUDA implementation
uses a CuPy raw kernel with shared-memory source tiles and several target
bodies per thread (register blocking), following the core optimisation pattern
in NBody-EuroHPC's `SimulationNBodyCUDATileFullDevice`. Bodies are packed as
coalesced (x, y, z, m) records, and the block size and targets per thread are
autotuned on the GPU running the job rather than fixed for one card.
The reference is MIT-licensed; no OpenGL renderer or source file is copied.

`--precision fp32|mixed|fp64` selects the arithmetic. `mixed` keeps positions,
velocities and force sums in FP64 but evaluates each pair in FP32, removing the
float32 summation bias that otherwise produces a slow spurious momentum drift
(about 1.5 km/s of centre-of-mass motion over 7.5 Gyr at 200k bodies). See
`docs/PERFORMANCE.md` for measurements and hardware guidance.

The particles are galaxy-scale super-particles and the generated initial
conditions are **not** fitted equilibrium models of the Milky Way and M31.
They are suitable for an educational visualisation, not a precision prediction
of the Local Group's future. Softening suppresses singular two-body scattering,
and the integrator enforces an approximately 24 Myr maximum step regardless
of the number of requested presentation frames.

## Observational morphology

The bundled reduced asset is generated by `tools/fetch_galaxy_catalogs.py`:

- [Gaia DR3](https://gea.esac.esa.int/archive/documentation/GDR3/) supplies
  measured distances plus Galactic longitude/latitude for a 3-D Milky Way seed
  sample. Because that magnitude/distance sample is local and obscuration is
  severe, its measured radial and vertical seeds condition an analytic
  four-arm disc rather than being mislabelled as a complete Galactic map.
- [PHAT v3](https://datalab.noirlab.edu/data/phat) supplies M31's observed sky
  pattern and stellar colours. The positions are deprojected at position angle
  38 degrees and inclination 77 degrees. PHAT does not provide useful
  per-star line-of-sight depth at M31, so the vertical coordinate is explicitly
  modelled. The surveyed side is reflected to complete the display disc.

The catalogue provenance and these transformations are stored in each run's
metadata and displayed in the rotatable viewer.

## Viewer and run contract

Alongside each JPEG, the solver writes
`interactive/frame_NNNN.json`: 3-D positions, galaxy identity, structural
component, catalogue-conditioning flag, time, and display extent. Leonardo
runs above 9,000 particles are deterministically sampled only for this browser
payload; the full particle set remains in the computation. Drag rotates the
camera, the wheel zooms, double-click resets it, and the dark-halo control can
hide/show halo particles while timeline playback continues.

The generic headless launch works unchanged:

```bash
python run_demo.py galaxy_collision_3d --profile hpc --backend gpu --frames 80
sbatch --export=ALL,DEMO=galaxy_collision_3d,BACKEND=gpu slurm/run_demo.sbatch
```

The same run can use `--backend cpu` on Leonardo DCGP or `--backend hybrid` on
the Booster partition. All output is filesystem based; no X server or OpenGL
context is required on a compute node.
